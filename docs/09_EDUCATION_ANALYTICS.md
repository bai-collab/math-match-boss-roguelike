# 09｜教育設計、提示階層與可解釋行為分析

## 1. 教育目標與證據限制

設計意圖是促進：

- 數字分解／組合與加法心算；
- 比較不同數字路徑與加數個數；
- 資源管理下的數學策略選擇；
- 說明「為何選這條路」的反思。

這些是**預期可練習的活動**，不是已經證明的教學成效；若要對外聲稱提升數學能力，需建立有效測量與對照研究。

## 2. 提示鷹架（初始建議）

- **第 0 層**：僅顯示弱點數字、連線長度限制與玩家當前路徑總和。
- **第 1 層**：顯示「目前總和 15，目標 17，相差 2」及總和大小關係。
- **第 2 層**：顯示數字拆解方向，不指出完整盤面路徑（例：還需 +2）。
- **第 3 層**：顯示一個可能的起點或亮一小段合法路徑。
- **第 4 層**：依教師設定可完整示範一條路徑，但該次記錄為「有完整提示」。

提示要**有開關與可追溯的使用紀錄**；局外升級可開啟更多提示類型，但不可讓玩家在沒選路的情況下自動完成破防。若未來對接課程，可設教師模式暫停戰鬥或關閉局外成長。

## 3. 匿名／最小化事件模型

```json
{
  "event":"PATH_COMMITTED",
  "runId":"local-random-id",
  "seed":12345,
  "turn":3,
  "enemyId":"goblin",
  "target":17,
  "color":"red",
  "tileValues":[3,5,9],
  "pathLength":3,
  "sum":17,
  "isExact":true,
  "hintLevelUsed":0,
  "decisionTimeMs":7300,
  "resultingPower":18,
  "timestamp":"ISO8601"
}
```

不需記錄學生姓名、學校、班級、電子郵件、音訊或鍵盤完整輸入。初版紀錄僅留本機，提供清除及停用選項。未經使用者決策／法規與倫理評估，不提供預設遠端同步或教師可識別個別學生的後台。

## 4. 可做的描述性分析

- 精確命中率：`exactCount / validCommittedPaths`，須按不同敵人弱點與是否使用提示分層。
- 決策時間：從盤面可互動到成功提交的時間；需排除暫停、切頁與動畫時間。
- 路徑長度分布、攻防療顏色選擇、弱點相差值、無解救援次數。
- 策略轉換：上一回合紅珠→藍珠，或有防禦意圖時是否改選防禦；**只描述可觀察行為，不推定心智狀態**。

## 5. Weight-Space-handwired 的合理接點

來源：[`bai-collab/Weight-Space-handwired`](https://github.com/bai-collab/Weight-Space-handwired) 的 `README.md` 與 `examples/handwired-basics.mjs`，已確認其使用 `score = relu(W·f+b)` 與可解釋權重貢獻的範例。

未來可從匿名遊戲事件抽出 `f=[exactRate, averageDecisionTimeNormalized, nearMissRate, hintUsageRate, defensiveResponseRate, reshuffleUsageRate]`，設計可解釋樣態計分，例如「需要提示」「採用防禦策略」「反覆嘗試」。**這些是規則分數，不是已驗證的學習能力或心理計量機率**；需要教師標註與可靠度檢查才可用於教育判定。

**不可將 handwired 放在正確性判斷迴路**：`3+5+9=17` 直接用整數運算，完全不需要模型。

## 6. 資料倫理／無障礙

- 預設不收集可識別身分資訊；資料分享須有清楚目的、保存期限、告知及權限管理。
- 不用玩法紀錄自動給學生貼「低程度」「懶惰」標籤。
- 色盲辨識：顏色＋圖案＋文字。
- 避免反覆閃光；支援 reduced motion、低音量／靜音與慢速提示。
- 顯示目標與差距時注意不洩漏完整答案；教育模式可要求學生在操作後先口述／寫下算式，再由教師使用。
