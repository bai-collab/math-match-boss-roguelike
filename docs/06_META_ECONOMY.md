# 06｜局內獎勵、局外成長與經濟平衡

## 1. 三種狀態不要混用

- **永久局外資料（MetaState）**：跨局貨幣、已解鎖角色、四條局外成長等級、是否完成教學；保存在 localStorage。
- **單局資料（RunState）**：目前 seed、地圖、HP、局內金幣、遺物、臨時道具、技能、Boss 進度；這一局結束後歸檔。
- **單場戰鬥資料（BattleState）**：盤面、當前怪物弱點、行動次數、敵人意圖；結束戰鬥後不保留盤面。

## 2. 局外商店（四線三階的設計提案）

| 路線 | T1 | T2 | T3 | 原則 |
|---|---|---|---|---|
| 勇氣／生存 | 基礎生命 +5 | 基礎生命 +10 | 基礎生命 +15 | 只提高容錯，不自動解數學題 |
| 智慧／提示 | 可看總和差距 | 可看合理的數字組合 | 每戰可看一次路徑起點 | 提示使用量記錄；不可默認學生能力不足 |
| 技巧／操作 | 每戰重整一次 | 每戰重整兩次 | 可將一顆珠 `±1` 一次 | 使用技能是主動決策，不能自動算好路線 |
| 探索／情報 | 提前預覽一格 | 額外事件選擇 | Boss 限制提前展示 | 重在資訊與路線策略 |

初版每階費用可設 `costs=[40,80,140]`，並引入局外貨幣 `晶片`（暫名）。**不應直接把作文遊戲的「墨水」移植過來**；價格尚未測試。

### 強化快照

開始新局執行：

```
run.metaSnapshot = structuredClone(meta.upgrades)
```

在局內即使日後可以打開局外商店，變更也只能對下一局生效。試玩／自動示範不賺貨幣、不解鎖永久成就，避免混入正式紀錄。存檔資料必須含版本欄位及驗證／升級機制。

## 3. 局內遺物範例（永久不保存）

- `四連破甲`：每次四消，額外獲得小額破甲值，但 Boss 仍需完成數學封印。
- `綠葉晶核`：第一次在戰鬥中以綠珠命中弱點時，額外回復 2 HP。
- `精準鏡片`：若紅珠總和正確，首次命中再 +2 傷害。
- `戰術護符`：每場首條藍珠路徑護盾額外 +2。
- `數字鐵砧`：每戰一次，可手動選擇一顆珠做數字 +1 或 -1（仍保持 1～9）。

**遺物觸發必須遵守順序**：原始算術 → 弱點／長度倍率 → 遺物加成 → 護盾／治療上限 → 寫入 log。任何遺物不得讓錯誤數學總和被標示為精確命中。

## 4. 局內商店／營火／事件

- 商店以 `gold` 購買小型回復、一次重整、臨時遺物，價格可調。
- 營火選一：恢復生命（依上限百分比）、升級當局遺物、清除一個負面狀態；最初可只做回血。
- 數學試煉：在有限次行動內合計指定數字，勝利取得額外 `gold` 或一件遺物，失敗不應直接造成不可逆的教育挫折。
- 事件室：二選一的資訊與資源取捨，初版不需要大量敘事文案。

## 5. 戰敗也要有意義，但不能鼓勵故意輸

- 正常結算可依走過層數、擊敗怪物、完成數學挑戰給少量局外貨幣。
- 通關獎勵可以較高，但不應只有勝者取得資源。
- 限制重複刷第一層、刻意放棄後大量重置獲幣。初版可用「每局固定結算一次＋關卡完成證明」。
- 教學獎勵與遊戲平衡分開；不要為了賺更多貨幣鼓勵學生亂點或刷失敗。

## 6. 平衡監測（後續實測）

每局：`turns`, `nodesVisited`, `bossPhaseReached`, `weaknessExactRate`, `relicsUsed`, `hintCount`, `rescues`, `win`, `currencyEarned`。分辨角色、種子、局外等級後比較；不要只看通關率。可用固定 100～1,000 個 seed 做 deterministic simulation，但**本計畫尚未執行任何這類試算**。
